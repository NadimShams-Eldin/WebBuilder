  للمراحل القادمة.

> هذا السجل مختصر للمعنى والقرار، وليس نصًا حرفيًا للجلسة. يُضاف إليه مع كل

## الجلسة 1 - إكمال v1 والتحقق من التصدير

### السياق
انتهت المراحل 0-14 من `docs/ROADMAP.md` (الحزمة الأساسية + الصفحات المتعددة +
الحركات + التصدير). آخر commit مدفوع حينها: `38d951a`
(feat(phase-14): live preview without editor chrome).

### ما جرى
1. مراجعة الحالة: المستودع نظيف مقابل `origin/main`.
2. المستخدم اختبر حزمة zip التجريبية: `index.html` + `about.html` + `styles.css`
   (بدون `script.js` لأنه لا توجد حركة تمرير)، والروابط تعمل، والناتج مطابق
   لـ `createDemoProject()`.

- اعتماد أن مولّدًا واحدًا يخدم الكانفا والمعاينة والتصدير (مصدر واحد للحقيقة).
- أوضاع العرض: `renderPageHtml(..., 'editor' | 'preview' | 'export')`.
- روابط الصفحات الداخلية: `page:{id}` في المحرّر/المعاينة، و`{slug}.html` عند التصدير.

## الجلسة 3 - طلب إعادة تصميم الواجهة كاملة (مصدر المسار UI)

### الطلب (مختصر المستخدم)
- نحتاج إعادة تصميم الواجهة الرسومية كاملة، بشكل يسهّل التفاعل ويوفّر الوقت بذكاء.
- أمثلة مستوحاة من Pinegrow:
  1. **شريط قوائم**: File, Edit, Page, Components, Window, Help — وفيه وظائف البرنامج.
  2. **تبويبات اللوحات قابلة لإعادة الضبط**: إخفاء/إظهار حسب راحة المستخدم،
     وإمكانية حفظ "لوحة مستخدم" خاصة.
  3. **شريط أدوات** + شارات تعريفية.
  4. **أدلة Grid تفاعلية**: شكل الحاوية عند استخدام Grid يظهر كأدلة تتفاعل مع
     زيادة/نقصان الأعمدة وتتغير بتغيّر الحاويات المطبَّق عليها.
- المستخدم أرفق 3 صور من Pinegrow (شريط قوائم + أدوات + لوحات + Timeline + قائمة
  سياقية + أدلة Grid).
- طلب أن أبحث موسّعًا وأصل لتفاصيل أدق مما وصفه.
- **ثم طلب صريح**: توقف عن البناء المباشر. سجّل الخطة، وقسّمها مراحل، واعرض
  المراحل أولًا، وراجعها قبل التنفيذ، وكل مرحلة تُسلَّم منفصلة.

### القرار
- عدم البناء دفعة واحدة. توثيق خطة مراحل مستقلة في `docs/UI_REDESIGN.md`.
- وضع السقالة الجزئية (شريط قوائم/أدوات/تبويبات) جانبًا في `git stash` مؤقتًا
  لإعادة بنائها مرحليًا: `stash@{0} - wip: ui redesign scaffold`.

### ما رصدته من الصور (تحليل)
- شريط قوائم أعلى + شريط أدوات بأيقونات مجمّعة (Undo/Redo، أجهزة، تكبير، Grid،
  إظهار/إخفاء لوحات).
- شجرة دومين (DOM tree) على اليمين بشارات نوع العناصر وكلاساتها.
- قائمة سياقية (كليك يمين) على تبويب ملف/صفحة: Open/Save/Duplicate/Delete/Rename...
- قائمة سياقية على عنصر: Transform/Opacity/Text/Background/Border/Shadows/
  Not animated CSS/Media/Class/Attributes/Scroll/DOM/SVG/Lottie/Interactions.
- لوحة حركات زمنية (Timeline) بمفاتيح (keyframes) وأزرار تشغيل.
- **أدلة Grid/Cols** فوق الكانفا مع مقابض لتغيير الأعمدة والفجوات مباشرة.

## الجلسة 4 - اعتماد خطة المراحل وترتيب العمل

### القرار المتخذ
- اعتماد مسار واجهة مستقل باسم **U0-U15**، مُوثّق في `docs/UI_REDESIGN.md`،
  ويُنفَّذ على **5 دفعات**:
  - الدفعة 1 (الأساس): U0 (تفضيلات التخطيط) -> U1 (شريط القوائم) -> U2 (شريط
    الأدوات + شريط الحالة) -> U3 (تبويبات الصفحات + القشرة).
  - الدفعة 2 (الراحة): U4 (لوحات قابلة للتحجيم/الطي) -> U5 (إعادة تصميم المفتّش)
    -> U6 (الشجرة + شريط المسار).
  - الدفعة 3 (البصرية): U7 (أدلة Grid/Flex التفاعلية + مسطرة + snap).
  - الدفعة 4 (السرعة): U8 (قوائم سياقية) -> U9 (لوحة أوامر + اختصارات).
  - الدفعة 5 (التخصيص): U10 (مساحات عمل محفوظة).
  - متقدّم لاحقًا: U11 (مكتبة مكوّنات) -> U12 (Timeline) -> U13 (تفاعلات) ->
    U14 (مدير أصول) -> U15 (نشر سحابي).

### ضوابط كل مرحلة (Definition of Done)
1. `npm test` + `npm run lint` + `tsc -b` تمرّ.
2. اختبارات وحدة لما يمكن اختباره.
3. تحديث `README.md` و`docs/ROADMAP.md`.
4. `git commit` + `git push origin main`.
5. إرسال رابط المعاينة.

### القرار الحالي
- **متوقف عن البناء** حتى يقرأ المستخدم الخطة ويوافق/يعدّل.
- حفظ سجل المناقشات (هذا الملف) ورفع المشروع للتوثيق.

## الجلسة 6 - تنفيذ الدفعة 2 (U4-U6)

### الطلب
"تابع إن كانت لديك خطوات تالية." (استكمال الدفعة 2 المتفق عليها: U4 -> U5 -> U6).

### ما نُفّذ (الدفعة 2 كاملة)
- **U4 (لوحات قابلة لتغيير الحجم)**: `PanelResizer` (سحب يُحفظ مباشرة) مع حدود
  دنيا/عليا (`200..480px`, افتراضي `288`) و`clampPanelWidth`، و`PanelCollapseStrip`
  على الحافة عند الطي بدل الاختفاء المفاجئ. العروض تُحفظ في `qitma-layout`
  (`widths.left/right`) وتُطبَّق مباشرة على `RightPanel`/`LeftPanel`. اتجاه السحب
  يتبع اللغة (RTL/LTR).
- **U5 (إعادة تصميم المفتّش)**: مكوّن `StyleInspector` جديد: شارات سريعة
  (display/gap/عدد الأعمدة)، حقل بحث يفلتر الخصائص، مبدّل "عرض الكل/المستخدمة فقط"،
  أقسام قابلة للطي، قيم جاهزة (chips) ووحدات منسدلة (`px/%/rem/em/vw/vh`).
  أُضيف قسم `effects` ونُقل إليه `boxShadow` مع `opacity`، وأُضيفت أوصاف
  `unit`/`quick` لبنية `StyleField`. استُخرجت المنطق النقي إلى
  `src/editor/styleInspector.ts` (+ اختبارات)، واستُخرج `FieldControl` إلى ملف مشترك.
- **U6 (الشجرة + المسار)**: شارات نوع ملوّنة حسب الفئة + عدّاد الأبناء، بحث في
  الشجرة يعرض المطابقات مع أسلافها، تحديد متعدد (Ctrl/Cmd للتبديل، Shift للمدى)
  مع شريط عمليات جماعية (تكرار/حذف)، وشريط مسار `Breadcrumb` أسفل الكانفا يعرض
  المسار من الجذر للعنصر المحدد وقابل للنقر. أُضيف إجراءان في المخزن
  `duplicateNodes(ids)` و`deleteNodes(ids)` (يُستخدمان أيضًا من الإجراء الفردي)،
  وأُضيفت `getPathNodes` + `src/editor/outlineSelection.ts` (منطق الشجرة النقي + اختبارات).

### النتيجة
- commits: `feat(U4)`, `feat(U5)`, `feat(U6)`, ثم تحديث الوثائق.
- 97 اختبارًا ناجحًا، lint نظيف، typecheck نظيف.

### القرارات
- التحديد المتعدد محليّ داخل `LayerTree` (مجموعة إضافية فوق العنصر الأساسي
  `selectedId`) ولا يغيّر دلالات السجل (history) — الأمان أولًا. العمليات الجماعية

- تبقى قاعدة عدم الحذف: لا حذف لأي مكوّن؛ القديم غير المربوط باقٍ في المستودع.
